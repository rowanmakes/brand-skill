# 基础：这个项目的来龙去脉

整理自用户与 Claude 的对话（2026-10-22 至 2026-10-28）。以后改这个仓库之前先读这份：用户说过什么、定过什么、为什么现在是这个样子。

UI/UX 设计在另一个仓库 [uiux-design-skill](https://github.com/rowanmakes/uiux-design-skill)，本文件不涉及。

## 1. 为什么有这个仓库

- 用户（2026-10-22）："品牌设计是一个独立的设计，和我们原本的是两个方向，但是我们没有品牌设计方向的东西，之后对于品牌设计方面比较匮乏。"
- 用户随后新建了这个仓库。
- 产出：Logo、字体、色板、语气、品牌规范。目标和 UI Skill 一样：惊艳，一眼不像 AI 模板。
- 和 UI Skill 的接口只有一个：品牌规范作为 UI Skill 写 DESIGN.md 时的输入。

## 2. 调研结论（10-22）

详见 `docs/research/2026-10-22-brand-survey.md`。

- **Lovart 的方法论**（用户问"是否可行"）：五层结构（承诺 → 人群角色卡 → 视觉规范 → 语气 → 触点）当骨架可用；但"形容词直接推颜色""生成 10 个 Logo 再挑"会做出标准答案，不会惊艳。可借：先定规则再出图、三秒辨识测试、角色卡写具体。
- **要不要找更多品牌 skill**（用户问）：找了 6 个，选定底座候选：
  - **brand-identity-skill**（MIT）：一个想法同时出 Logo、字体、颜色；三套方向并排、停下让用户挑；对照真实竞品；AI 默认清单；脚本量对比度、色盲、小图、字体授权；有测试数据。
  - **BrandDesign**：先出黑白草图、独立评审、全套物料。
  - **claude-brand-skills**：先写品牌情绪、二选一不混合。
- **和 UI Skill 的共同点：** 模型会滑向默认外观；多方向并排让用户挑；"换个同类品牌还成立吗"。

## 3. 用户定下的做法

| 日期 | 决定 |
| --- | --- |
| 10-22 | 品牌设计独立成一个仓库，和 UI Skill 分开 |
| 10-22 | 品牌测试在用户本地跑，不在 Claude 云端跑 |
| 10-22 | 不想自己找感觉（"就像大海捞针"），要 agent 来挑，用户只做判断 |
| 10-25 | **字体不建库、不获取别人的字体文件**，采用 Anthropic frontend-design 的做法；只用 Google Fonts 等合法来源或已授权的字体 |

之前讨论过、现已取消：中文字体库、把字体存到用户的服务器、让 Kimi 去核对字体许可。

## 4. 已知的风险

- **中文字体可选很少。** 云端预检时，"衬线 + 中文"只搜到 1 款，三套方向可能撞同一款中文字。不建库的前提下，靠字重、字宽、标题排法和英文字体拉开差别。
- **中文品牌的字标通常是画出来的，不是直接打字体。** 底座支持在字形上画细节，这是品牌 Skill 在中文上真正要发力的地方，B0 重点看。
- 底座只在 Claude Code 上测过；用户的模型组合跑出来怎样未知。

## 5. 工作原则（沿用 UI Skill）

- 先测试，再加规则；B0 出结果前不写 Skill 本体。
- 奥卡姆剃刀：先原样用底座，坏在哪补哪。
- 多个方向并排，停下来让用户挑，绝不替用户选。
- 能量的交给脚本，不能量的标"判断"；不编 Pantone、CMYK、商标检索结论。
