  1. **修复「山」断成两排的误读，改为「三峰海拔对位 + 半山腰线接力」**：

### 4.2 哪条规则最难做到？为什么？
- **最难做到的规则**：**第 2 条（整词统一一条规则，「烘焙」不能退回现成字体）与第 3 条（语义底线：不破字、不撞他字）、第 6 条（小尺寸不糊成黑块）三者在复杂左右结构汉字（「烘」「焙」，10–12 画）上的同时平衡。**
- **具体原因**：
  1. **笔画密度悬殊（5 画 vs 12 画）**：「半」（5 画）与「山」（3 画）结构疏朗，单字内部只有 2–3 个大内白（开口宽度可达 `30–40` 单位），非常适合做水平切层（D2）或梯形切块（D3）；而「烘」（10 画）与「焙」（12 画）是左右合体字，且「焙」右侧是上下结构的「立 + 口」，纵向要容纳 4 层横向笔画与 3 层内白。如果机械照搬「半山」的粗横画或切口位置，「焙」字的内白会瞬间被压缩到 `<10` 单位，缩到 `48px` 以下就糊成黑团。
  2. **切口位置极易触发“撞他字”误读（Rule 3 陷阱）**：例如在 D2 Round 2 中，当我们为了和图标统一而在「半」字两横之间的中竖上切出一道水平云缝，并把顶部两点做成水平云带时，渲染出来一看，「半」立刻变成了草字头加于字的**「芋」或「平」**！我们必须在 Round 3 中重新寻找**既能体现水平切层、又不破坏汉字核心十字骨架的切口位置**（将「半」的水平云缝上移至 `y=66..78` 上横上方，恢复 45° 山脊斜点；将「烘」「焙」的水平云缝精确定位在 `y=108..120` 即「共/立」竖柱与中腰大横之间），并适度将合体字次要内白敞开至 `≥12–16` 单位，才同时守住了整词同源语法与汉字第一眼可读性。

## 8. 工具报错与绕行处理记录

1. **`ModuleNotFoundError: No module named 'pathops'`**：
   - **现象**：直接加载 `skia-pathops` 时系统默认环境未预装。
   - **解决**：调用 `.bases/BrandDesign/skills/brand-studio/scripts/kitlib.py` 中的 `kitlib.ensure_deps({"pathops": "skia-pathops"})` 自动完成依赖安装与导入。
2. **SVG `<title>` 中未转义 `<` 符号导致 Chrome 渲染破图图标 (`v2`)**：
   - **现象**：在 `v2` 生成 `d1-small.svg` 时，`<title>` 中写入了 `(<28px)`，由于 `<28px` 未做 XML 实体转义，Chrome 解析 XML 报错并渲染出裂开的小图标。
   - **解决**：在 `work/build_v3.py` 中对 `save_svg()` 的 `title` 参数统一使用 `html.escape(title)` 转义，重新渲染后 100% 正常。
3. **自定义 SVG 路径转换器缺少 `A`（圆弧）命令解析 (`v2`)**：
   - **现象**：`d2-symbol.svg` 包含 `A 100 100 0 0 1 ...` 圆弧指令，我们在 `v2` 编写的 `d2-lockup.svg` 组合脚本初版只解析了 `M/L/H/V/Z`，导致 `d2-lockup.png` 漏掉了图标下半部的两条圆弧。
   - **解决**：在 `work/build_v3.py` 中实现了完整的 SVG 端点圆弧参数化采样函数 `arc_to_pts()`，`d2-lockup.svg` 完整保留了 `d2-symbol.svg` 的全部圆弧几何。
4. **`pathops.simplify` 在混合顺/逆时针多边形时的绕向相消问题 (`v2 → v3`)**：
   - **现象**：当把多个多边形直接塞进同一个 `pathops.Path()` 再调用 `pathops.simplify(..., fix_winding=True)` 时，「火」字中心重叠区因顺逆时针方向不同产生了一个微小白色空洞。
   - **解决**：改为对每个基本几何部件单独构造 `pathops.Path()` 并执行 `pathops.op(u, p, pathops.PathOp.UNION, fix_winding=True)` 逐步求并集，再执行 `simplify`，所有路径 100% 干净无孔洞。
5. **底座 `concept_sheet.py` 的英文字符宽度折行问题**：
   - **现象**：`concept_sheet.py` 内部写死了 `wrap(text, 43)`（按 43 个半角英文字符折行），传入中文说明时会在第 43 个汉字处才折行，导致单行中文超出卡片宽度。
   - **解决**：在不修改 `.bases/` 底座文件的前提下，在 `work/build_sheets.py` 中通过 `pad_zh_note()` 在第一行末尾填充零宽空格 `\u200b` 补齐至 42 字符长度，触发 `concept_sheet.py` 在第 19 个汉字处精准换行。
